# GregClicker — MVP

Инкрементальный кликер-автоматизатор на Godot 4 по мотивам GregTech: New Horizons.
MVP покрывает эпохи 0–2 (каменный век → пар → LV) на одном острове: от первого бревна
до стали из электродуговой печи (EBF) и первой MV-схемы. Ориентир — 5–10 часов игры.

Дизайн-документ — источник правды; все отступления от него записаны в [DECISIONS.md](DECISIONS.md).

## Требования

- **Godot 4.7.x** (проверено на 4.7.2 stable). Никаких аддонов не нужно.

## Запуск

1. Откройте папку проекта в редакторе Godot 4.7 и нажмите F5.

   Без редактора — один раз импортируйте проект (строит кеш классов в `.godot/`), потом запускайте:

   ```bash
   godot --headless --import --path .
   ```

   ```bash
   godot --path .
   ```

2. Сохранение — `user://saves/save_0.json` (на Linux: `~/.local/share/godot/app_userdata/GregClicker/`).
   Автосейв раз в 60 секунд и при закрытии окна.

## Тесты и проверка

Полная проверка перед коммитом — импорт, линт (все предупреждения GDScript считаются ошибками),
запуск главной сцены и все тесты:

```bash
tools/check.sh
```

Путь к Godot можно передать аргументом или через переменную `GODOT`:

```bash
GODOT=/path/to/godot tools/check.sh
```

Только тесты (собственный раннер на чистом GDScript, без аддонов):

```bash
godot --headless --path . res://tests/test_runner.tscn
```

Один файл или тест — фильтр по подстроке имени `файл::метод`:

```bash
godot --headless --path . res://tests/test_runner.tscn -- --filter=offline
```

Сквозной тест «бот проходит MVP» с подробной хронологией прохождения:

```bash
godot --headless --path . res://tests/test_runner.tscn -- --filter=bot --verbose
```

Что покрыто: форматирование чисел (4 режима) и насыщение int64, атомарное списание из хранилища,
формулы оверклока/энергии/апгрейдов, баланс кликов, дефицит энергии и батареи, котлы,
офлайн по событиям против пошаговой симуляции 18 000 тиков, сохранение → загрузка → миграция,
резервные копии, экспорт base64, открытие рецептов по discovered, квесты, майнеры и жилы,
валидатор данных, полнота переводов, дымовой тест интерфейса и бот, проходящий все 40 квестов.

Скриншоты всех экранов без редактора (нужен Xvfb):

```bash
xvfb-run -a -s "-screen 0 1600x900x24" godot --path . --rendering-driver opengl3 res://tools/screenshot.tscn -- --out=/tmp/shots
```

## Управление

| Клавиша | Действие |
|---|---|
| `1`–`7` | вкладки: Карта, Хранилище, Станции, Квесты, Наковальня, Энергосеть, Настройки |
| `Esc` | закрыть окно / вернуться на карту / снять выбор блока |
| `F12` | debug-панель |
| ЛКМ по блоку | удар; **зажать** — автоклик 5 раз в секунду; клик по искре — урон ×5 |
| ЛКМ по полосе прогресса станции | ускорить текущий крафт на 0.2 с |
| `Shift` / `Ctrl` + «Крафт» | крафт ×10 / максимум |
| ПКМ по предмету в хранилище | «где добыть / где используется» |

Вкладки скрыты, пока не открыты по ходу игры (5 брёвен → хранилище, верстак → станции, печь → квесты…).

## Debug-панель (F12)

- **Выдать предмет**: поиск по имени или id, количество, «Выдать».
- **Скорость времени**: ×1 / ×10 / ×100 / ×1000 и «+1 игровые сутки» (смена жил).
- **Открыть эпоху** 1 или 2: ставит эпоху и открывает все вкладки и зоны.
- **Симулировать офлайн** N часов: та же событийная перемотка, что при загрузке сейва, с окном-отчётом.

## Структура проекта

```
data/            всё содержимое игры в JSON (единственное место, где живёт контент)
  balance.json     все коэффициенты баланса
  materials.json   материалы, формы и шаблоны рецептов по формам
  items.json       предметы, которые не генерируются из материалов
  stations.json    станции, стоимость апгрейдов, мультиблоки
  power.json       котлы, турбины, генераторы, батареи
  miners.json      типы майнеров
  recipes/*.json   рецепты по группам станций
  dimensions/      карта острова: тайлы, блоки, рудные жилы
  quests/*.json    главы квестов
  unlocks.json     условия открытия вкладок и систем (онбординг)
core/            симуляция: автолоады без графики + классы определений (core/defs)
ui/              интерфейс: читает состояние автолоадов и шлёт им команды
audio/           шина звука и генератор звуков-плейсхолдеров
i18n/strings.csv переводы: ключ, en, ru
tests/           раннер, тесты и бот
tools/           check.sh, линтер, скриншоты
```

Автолоады (порядок важен): `Events` (шина сигналов), `Registry` (данные и валидатор), `Settings`,
`GameClock` (время, сутки, перемотка), `Storage`, `Progress` (эпоха, открытия, статистика),
`Tools` (пояс инструментов), `World` (блоки, жилы, ручная добыча), `Power`, `Stations`, `Miners`,
`Quests`, `Save`, `Sfx`.

При запуске `Registry` проверяет данные: битые ссылки, предметы, которые нельзя получить,
циклы в квестах, неиспользуемые предметы. Ошибки печатаются в консоль с понятным текстом.

## Как добавить контент

Всё делается в JSON; код трогать не нужно. После правки запустите `tools/check.sh` —
валидатор и бот сразу покажут, если что-то стало недостижимым.

### Предмет

`data/items.json`:

```json
{"id": "graphite", "icon": "lump", "color": "#30343a", "era": 2, "tags": ["carbon", "fuel"], "fuel": 6000}
```

- `icon` — имя серой формы (`ingot`, `dust`, `plate`, `gem`, `lump`, `machine`… — см. `ui/icons.gd`);
  иконка перекрашивается в `color`. Свой рисунок: положите `art/icons/<форма>.png` (16×16, серый).
- `unit: "liter"` — жидкость (показывается как «144 L»).
- `kind`: `item` (по умолчанию), `station`, `generator`, `miner`, `part` (деталь мультиблока).
- `fuel` — для твёрдого топлива литры пара за штуку, для жидкого — EU за литр.
- Имя: добавьте строку `ITEM_GRAPHITE,Graphite,Графит` в `i18n/strings.csv`
  (необязательно `DESC_GRAPHITE` — описание в тултипе).

### Материал (автогенерация руды, пыли, слитка, пластины, стержня, провода)

`data/materials.json` → `materials`:

```json
{"id": "lead", "color": "#6a6a8a", "era": 2, "forms": ["ore", "dust", "ingot", "plate"], "flags": ["smeltable"]}
```

Предметы `lead_ore`, `lead_dust`… и рецепты по шаблонам `form_recipes` (переплавка, дробление,
молот, волочение) появятся сами. Блок `"tool": {...}` добавит кирку, топор и лопату этого тира.
Переводы: `MAT_LEAD` и `MAT_LEAD_GEN` (родительный падеж: «Слиток свинца»).

### Рецепт

Любой файл в `data/recipes/`:

```json
{"id": "as_graphite_rod", "station": "lv_assembler",
 "inputs": [{"item": "graphite", "n": 2}, {"tag": "carbon", "n": 1}],
 "outputs": [{"item": "steel_rod", "n": 1}, {"item": "coal_dust", "n": 1, "chance": 0.25}],
 "ticks": 200, "eu": 16, "req": {"heat": 1500}}
```

`ticks` — тики GT (20 в секунду), `eu` — EU/t. Вход `tag` принимает любой предмет с тегом.
Рецепт виден игроку, когда все входы хотя бы раз были получены.

### Станция

`data/stations.json` + предмет с `"kind": "station"` и рецептом его крафта:

```json
{"id": "lv_lathe", "item": "lv_lathe", "energy": "eu", "voltage": "LV", "era": 2,
 "speed_cost": [{"item": "electric_motor", "n": 1}], "efficiency_cost": [{"item": "copper_wire", "n": 8}]}
```

### Квест

Файл главы в `data/quests/`:

```json
{"id": "q2_graphite", "pos": [3, 2], "requires": ["q2_wiremill"], "main": false, "icon": "graphite",
 "goals": [{"type": "obtain", "item": "graphite", "n": 16}],
 "rewards": {"items": [{"item": "coal", "n": 32}]}}
```

- Цели: `obtain` (получено за игру), `have` (есть сейчас), `craft` (можно `station`), `break` (`node`),
  `stat` (`steam_gen`, `eu_gen`, `miners`, `ebf_built`, `era`, `repairs`, `clicks`), `checkbox`.
  Вместо `item` можно `tag`. Логика целей — `goals_mode: all | any`, связей — `requires_mode`.
- Награды: `items`, `choice` (выбор одного из вариантов), `unlock` (id из `unlocks.json`), `era`, `demo_end`.
- `visibility`: `visible` / `locked` / `hidden`. `pos` — клетка на полотне главы.
- Тексты: `QUEST_Q2_GRAPHITE` и `QUEST_Q2_GRAPHITE_DESC` в `i18n/strings.csv`.

### Блок на карте

`data/dimensions/overworld.json` → `nodes`: позиция в тайлах, `tool_type`, `hardness`,
`min_tool_tier`, `vein_size` (лимит майнеров), `drops`, условие появления `reveal`
(`{"discovered": "furnace"}`, `{"era": 1}`, `{"quest": "id"}`, `{"any": [...]}`).
Рудные жилы — массив `veins`; ячейки «Рудных холмов» с `vein_slot` меняют жилу раз в игровые сутки.

### Моды

JSON с массивами `items` и/или `recipes` в `user://mods/*.json` подмешиваются при запуске.
